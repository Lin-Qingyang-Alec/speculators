# Speculators — Agent Guide

## Scope and project overview

This guide applies to the whole repository. Read any more specific `AGENTS.md` before changing files in its directory. Use the checked-out source, `pyproject.toml`, and CI configuration to verify commands and interfaces; some tutorials describe older implementations.

Speculators is a Python library for training, converting, and saving speculative decoding draft models for serving with vLLM. The pipeline prepares data, extracts verifier hidden states online or offline, trains a drafter, and evaluates acceptance and serving performance. Current algorithm modules are `eagle3`, `peagle`, `dflash`, `dflash2`, `dspark`, `mtp`, `xpress`, and experimental `pmtp`.

## Environment and installation

- Python must be **3.10 or newer**. Quality CI checks Python 3.10 and 3.13; keep syntax compatible with the declared minimum.

- Use an isolated environment. From the repository root, the documented development install is:

  ```bash
  python -m pip install -e ".[dev]"
  pre-commit install
  ```

- Keep Speculators training and vLLM in separate environments, as described in `docs/user_guide/tutorials/train.md`. Install `hs_connectors` in the environments that need its backends. E2E tests select the vLLM interpreter using `VLLM_PYTHON`.

- When editing `hs_connectors`, install the local package with `python -m pip install -e ./hs_connectors` in each relevant environment and verify that imports resolve to this checkout. Installing only the root package may select a published connector version.

- Base dependencies are in `[tool.speculators.dependencies].base` in `pyproject.toml`. Root `setup.py` computes the `hs-connectors` requirement and package version; `hs_connectors` has its own packaging metadata. Preserve this arrangement when changing dependencies.

- `version.py` and `version.txt` under both package source directories are generated by packaging. Change the build logic rather than editing generated versions.

- Training, serving, and the GPU CI scripts target Linux/CUDA environments. On Windows/PowerShell, use the explicit Python check commands below when GNU Make/Bash is unavailable, and use a suitable Linux/CUDA environment for GPU workflows.

- If Windows Python defaults to GBK, enable UTF-8 mode before running scripts that read repository sources: use `python -X utf8 ...` or set `$env:PYTHONUTF8 = "1"` in PowerShell.

## Development conventions

- Check `git status` before editing and keep changes focused. Preserve unrelated work and avoid repository-wide formatting for a narrow fix.
- Follow `pyproject.toml`: Ruff formatting uses 88 columns, four spaces, double quotes, and sorted imports. Add useful type annotations; use `pathlib` and the existing logging conventions.
- Keep algorithm-specific behavior in its module and reuse shared model, loss, and data utilities where appropriate.
- Preserve checkpoint/config serialization, verifier metadata, tensor shapes and dtypes, vocabulary mapping direction, and attention/loss-mask semantics. Cover changes to these contracts with relevant regression tests.
- Update affected CLI docs and examples when changing public behavior. Keep repository documentation and code comments in English, consistent with the existing files.
- For upstream contributions, follow the coordination guidance in `CONTRIBUTING.md`. When commits are requested, include the required DCO sign-off with `git commit --signoff`.

### Training configuration and algorithm extensions

- Both `speculators train` and `torchrun -m speculators.train` resolve configuration through `TrainConfig`. Its precedence is **CLI flags > YAML > defaults**. Preserve legacy flag handling, flattening, backend arguments, and saved `run.yaml` round trips.
- Define new training fields in `src/speculators/train/config/schema.py` and adjust resolution where needed. `src/speculators/train/cli.py` builds models and starts training; it is not the sole source of CLI field definitions.
- For a new algorithm, start with `docs/developer/add_algorithm.md` and a current implementation such as `src/speculators/models/eagle3/`. Register the config with `SpeculatorModelConfig.register(...)` and the model with `SpeculatorModel.register(...)`, using a consistent algorithm name.
- Follow the existing `from_training_args(...)`, `get_trainer_kwargs(...)`, `layers`, and `forward(...)` contracts consumed by the trainer. Match the current metrics interface in source rather than copying outdated documentation examples.
- Update the algorithm package exports and relevant public exports. Test registry discovery, config/checkpoint save/load, and the changed training behavior. Add conversion or vLLM compatibility coverage when those interfaces change.

### Generated provenance helper

`src/speculators/provenance.py` is the source of truth. `scripts/_provenance.py` is a generated copy so launch/evaluation scripts can run without installing Speculators in the vLLM environment. Keep those scripts independent of `speculators` imports.

After changing the shared helper, regenerate and verify it:

```bash
python scripts/sync_provenance.py
python scripts/sync_provenance.py --check
```

## Validation commands

Run commands from the repository root in the development environment. Start with tests relevant to the change, then run the applicable quality checks. Documentation-only edits need Markdown validation; they do not require a training run.

| Purpose                                                      | Command                                                                 |
| ------------------------------------------------------------ | ----------------------------------------------------------------------- |
| Full quality checks                                          | `make quality`                                                          |
| Automatic style fixes (modifies files across the repository) | `make style`                                                            |
| Hooks against all files                                      | `pre-commit run --all-files`                                            |
| Unit tests                                                   | `python -m pytest tests/unit`                                           |
| One test file or case                                        | `python -m pytest tests/unit/path/test_file.py` or append `::test_name` |
| Integration tests                                            | `python -m pytest tests/integration`                                    |
| E2E smoke workflows                                          | `python -m pytest tests/e2e/smoke`                                      |
| Build documentation                                          | `mkdocs build`                                                          |

`make quality` runs Ruff lint/format checks, mdformat for repository Markdown, Mypy, and generated-provenance parity. Without Make, run its checks directly; replace the example Markdown path with the files being validated:

```bash
python -m ruff check
python -m ruff format --check
python -m mdformat --check AGENTS.md
python -m mypy --check-untyped-defs
python scripts/sync_provenance.py --check
```

- Some unit tests also need CUDA/Triton or downloaded model configs; do not assume `tests/unit` is entirely offline or CPU-only. Inspect the selected tests and fixtures first.

- Reuse skip helpers in `tests/conftest.py` for CUDA, multiple GPUs, and version constraints, plus the markers declared in `pyproject.toml`: `smoke`, `sanity`, `regression`, `e2e`, `slow`, and `multi_gpu`.

- E2E workflows can launch servers, download weights, and perform training. Check their hardware, model-access, and `VLLM_PYTHON` requirements before running them. `.buildkite/scripts/run-tests.sh` documents the CI setup.

- Report the checks run and any missing prerequisites or skipped coverage. Do not treat an unavailable GPU or dependency as a passing test.

- For PMTP CPU model tests on Windows, use `python -X utf8 scripts/test_pmtp_cpu.py`. The runner disables CUDA and supplies an import-only `fcntl` shim that raises if Unix file locking is invoked. It does not validate online transport. See `docs/user_guide/pmtp.md`; PMTP checkpoints require a parallel proposer and cannot use `stitch-mtp`.

## Provenance

Training, eval, and vLLM-launch scripts write reproducibility artifacts so runs can be recreated later.

- **Training** (`src/speculators/train/utils.py`): `save_train_command()` writes `train_command.txt` (timestamp, git SHA, world size, package versions, full argv) and `speculators.patch` (uncommitted diff) into the checkpoint directory.
- **Eval** (`scripts/evaluate/evaluate.py`): `save_eval_provenance()` writes `eval_command.txt` (timestamp, git SHA, package versions, full argv) into the output directory.
- **vLLM launch** (`scripts/launch_vllm.py`): `_save_vllm_provenance()` writes `vllm_command.txt`, `vllm.patch`, and `checkpoint_sha256.txt` (plus `drafter_checkpoint_sha256.txt` in eval mode) — but **only when `--provenance-dir` is passed**. Two subcommands:
  - `launch_vllm.py train MODEL` (default): hidden-states extraction for training data generation.
  - `launch_vllm.py eval MODEL --spec-model DRAFTER`: speculative decoding serving for evaluation.

**Always pass `--provenance-dir` when running `scripts/launch_vllm.py`** — point it at the associated run's output/checkpoint directory (e.g. `--provenance-dir <output_dir>`) so the vLLM provenance is co-located with the training/eval it belongs to.

When publishing a model or eval results (HuggingFace, GitHub comments, etc.), always include the provenance artifacts (`train_command.txt`, `eval_command.txt`, `vllm_command.txt`, `checkpoint_sha256.txt`, `drafter_checkpoint_sha256.txt`, patches) so the run can be reproduced.

Preserve the associated `run.yaml` and other configuration artifacts as well. Provenance writers are best-effort in several scripts, so verify that the expected files were created before publishing results.

Launch examples with co-located provenance:

```bash
python scripts/launch_vllm.py train MODEL --provenance-dir RUN_OUTPUT_DIR
python scripts/launch_vllm.py eval MODEL --spec-model DRAFTER --provenance-dir EVAL_OUTPUT_DIR
```
